# 开工闸门（dsh-prework-gate）

给 DeepSeek Harness 用的插件：**先问清、再出清单、批准后才动手。**

它往系统提示里加一节高优先级规则，于是该 profile 的每个会话里，智能体都会：

1. 先澄清需求（目标、范围、约束、验收），最多问 4 个问题；能只读自查的自己查；
2. 先调研现成方案与当前状态，给出候选与取舍；
3. 出执行清单（步骤、影响面、风险、回滚方式、待定分叉）并请你确认；
4. 只有你明确批准后才开工；清单外的事重新确认。

纯只读问答、单行笔误修正、以及你当轮已给完整规格并说“直接做”的情况不触发。

## 安装

纯 Host 插件，无依赖、无构建步骤。

1. DSH 里打开 **插件** → **添加插件**，选本目录；或用 `plugin_manager` 工具
   （`action: install_bundle`，`target` 填本目录绝对路径）。
2. 列表里显示为 **开工闸门 / Prework gate**。在 `cordis.patch.yml` 里把
   `enabled` 改成 `false` 可关掉。

首次安装可通过 HMR 生效；替换已安装的包需要重启。

## 配置

```yaml
- insert:
    - id: prework-gate
      name: 'dsh-prework-gate'
      config:
        enabled: true          # false = 完全不注册
        order: 400             # 提示位置，越小越靠前、权重越高
        strictness: adaptive   # adaptive | always | strict
        extraRules: []         # 追加到规则末尾的补充条款
```

`order: 400` 位于内置的计划策略（500）和所有工具说明（1000+）之前，因此比
默认行为更“强势”。想弱化就调大这个值。

`strictness`：

| 取值 | 行为 |
| --- | --- |
| `adaptive`（默认） | 小改动（单文件、可回滚）：复述理解 + 问一句即可；其余走完整四步清单。 |
| `always` | 每个任务都走完整四步，不用任务大小做例外。 |
| `strict` | 完整四步 + 至少 2 个澄清问题 + 清单必须含风险与回滚列 + “你看着办”要先列 A/B 让你挑。 |

规则正文都在 `index.js` 的 `BASE_RULES` 和 `MODES` 里，改文案后重新安装即可；
项目级补充规则可以写进 `extraRules`。

## 验证

新开一个会话，发一句“帮我改一下配置”之类的话，或直接让我改个文件：正常应该
先复述需求、问清楚，再给清单，而不是直接写。

## 已知限制

- 这是提示词层面的闸门，不是硬拦截：能显著提高“先问再做”的概率，但无法在物理上
  阻止工具调用。需要强制时配合审批模式或 guard 类插件。
- 每个请求的系统提示会多出几百 token。
