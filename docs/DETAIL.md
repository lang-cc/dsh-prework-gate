# 开工闸门 / Prework gate

## 它做什么

往系统提示里注册一节规则（`prework-gate`），使本 profile 的所有会话在改动任何东西
之前，按固定顺序工作：

1. **澄清** —— 用 `ask_user_question` 一次问清目标、范围（含“不要动什么”）、约束、
   验收；能只读自查的自己查。信息已足够时跳过提问并说明。
2. **调研** —— 找现成方案/相似实现，确认可复用技能，只读摸清现状，给 2–3 个候选与
   取舍理由。
3. **清单** —— 任务理解一句话 + 调研结果 + 执行清单表（步骤 / 影响面 / 风险 /
   回滚方式）+ 待定分叉 + 请确认。每步可验证；中高风险步骤必须写明备份方式；删数据、
   改注册表、装服务、卸载、远程操作、对外发布单独标出。
4. **等批准** —— 只有明确回复「可以 / 开工 / 按这个做」才开始；批准只覆盖清单内步骤，
   清单外的重新确认；执行中要偏离清单先停下重问。

收尾报告「做了什么 / 怎么验证的 / 还差什么」。

## 不触发的情况（例外）

- 纯只读问答与解释；
- 单行零风险笔误修正；
- 用户当轮已给出完整规格并明说「直接做」。

例外发生时，智能体应先说一句“按例外直接做了”。

## 用法

安装后无需操作：规则随每次请求重新组装，新会话、续接会话都生效。

三种力度（`strictness`）：

- `adaptive`（默认）：小改动一句话复述 + 问一句；其余走完整四步。
- `always`：所有任务都走完整四步。
- `strict`：完整四步 + 至少 2 个澄清问题 + 风险/回滚列强制 + “你看着办”必须先给 A/B。

`order` 控制提示中的位置，默认 400：位于内置计划策略（500）与工具说明（1000+）之前，
因此在模型中权重偏高。调大即弱化。

`extraRules` 可追加你自己的条款，例如：

```yaml
extraRules:
  - '删除任何文件前，先列出绝对路径清单让我核对。'
  - '不要用桌面自动化代我点击界面。'
```

## 限制

- 提示词层面的约束，不是硬拦截：它大幅提高“先问再做”的概率，但不能在物理上阻止工具
  调用。需要强制时，配合审批模式（approval）或 guard 类插件使用。
- 每个请求的系统提示会多出几百 token。
- 只影响加载它的 profile；切换 profile 或禁用行即失效。
